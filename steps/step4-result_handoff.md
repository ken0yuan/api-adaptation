# Step4：结果交回

向调用方返回本批逐 API 结果及任务结果目录中的 `api-loop/result.json` 路径，包含适配策略、前序确定的类别、分流结论、测试文件、实际验证结果及后续步骤。

分别统计输入 API 数、策略为 `补充testcase` 的 API 数及成功生成用例的 API 数。实际运行后统计真实通过、失败及未完成项，不能用生成数量代替执行通过数量。

未运行的补测项说明已生成的文件和未运行原因。测试通过的API状态为`支持`，在api-adaptation内结束并交回主agent准备PR；普通的`待适配`项交 Step2。补测用例已明确目标平台不支持某场景时，保留实际执行结论和逐 API 状态，将用例与 Step1 记录的平台限制证据直接交主 agent 发布补测 PR。逐API状态必须已通过`record_api_status.py`写回本次`adapt-information.json.api-status`。当前其余三类为待评估，不称为已生成、已验证或不需要。后续产生逐类评估时，一并交回结论、依据及尚缺的生成能力。

适配项交回 Step2 设计、修改前证据、Step3 实际修改文件与符号、修复后实测报告及验收结论。只完成设计或仍有失败、阻塞时，保留待适配状态并标明恢复步骤。其他专项策略、生成失败或信息缺失分别说明原因。

根据本批结果提供 issue 和 PR 所需的问题描述、改动说明及验证材料；已有 issue/PR 信息从交接材料复用。由调用方统一提交 issue、commit、push 和上传 PR，本 skill 不独立发布。没有适配实现改动时如实说明仅补充了测试，不虚构实现缺陷。

本步完成表示当前材料已交回；整个任务是否完成，由调用方根据未完成项及实际发布结果判断。
