# 核对版本条件和原有路径

1. **目标版本跑对了吗？** 对照任务给出的 PyTorch 版本、实际加载的 torch 和 torch-npu 构建，以及目标调用的回归结果。nightly 记录实际构建版本。
2. **新增代码在哪些版本启用？** 看最终 diff 中的版本条件。核对新路径是否默认从本次目标版本起生效，后续版本能否继续走这条路径。若只匹配单一版本或设置了上限，检查是否有具体的接口限制。同一版本号无法区分接口差异时，检查能力条件。
3. **条件不成立时会怎样？** 对照改前源码，沿原入口走一遍。C++ 新声明、定义和对新枚举或符号的引用都应处于有效的编译条件内。Python 还要看模块导入阶段是否提前访问了新接口。旧版本原先没有该入口时，保留原来的可用范围。

在报告中分别写明目标版本的实测结果，以及对原有路径的源码核对结论。常规验收无需提供旧版源码、wheel 或重新编译旧版。若对某个条件或符号仍有具体疑问，指出疑点，再对该处做定向验证。
