# 核对实现与仓内规范

从最终 diff 找到真正改变行为的符号，连同它的入口和相邻实现一起读。判断本次改动是否正确，以当前 API 的契约和验证结果为依据。

- **实现是否落在正确的路径。** 从用户调用沿注册、分派或包装层走到修改处。涉及生成代码时，核对维护的源文件及实际构建使用的产物。
- **改动是否符合接口约定。** 对照 Step 2 引用的上游行为和仓内同类实现。只检查本次触及的约定，例如返回值归属、状态更新时机、异常处理或资源释放。发现差异时，写清什么输入或调用顺序会让用户观察到不同结果。
- **共用实现还有谁在用。** 核对同一符号的其他调用者。若其中一个入口需要不同语义，检查分支条件是否只选中该入口，并把受影响的行为带到回归核验。
